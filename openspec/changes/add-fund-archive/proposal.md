# Proposal: add-fund-archive

- Change ID：`add-fund-archive`
- 状态：Draft
- 规格范围：`fund-archive`

## Why

当前系统缺少统一的基金档案入口，基金基础信息与申购、赎回要素无法集中查看，人工维护的申赎规则也缺乏版本留痕。需要新增基金档案模块，并确保人工维护结果不会被后续 ETL 覆盖，同时保留历史记录供审计追溯。

## What Changes

- 新增「基金档案」Tab，页内设置「基础信息」和「申赎要素」两个区块。
- 提供基金档案分页查询及按基金代码查询详情的后端接口。
- 支持编辑申赎要素；每次保存均在事务内软删除当前生效记录、插入新的生效记录，不物理删除历史数据。
- 生效数据按 `MANUAL > ETL` 选择：存在生效人工记录时使用人工值，否则使用 ETL 最新生效值；后续 ETL 不得修改人工记录。
- 接口保留 `null` 与 HTTP 错误语义，前端将 `null`、空字符串及查询异常统一展示为 `--`，但数值 `0` 不得展示为 `--`。
- MySQL `gy_meta` 保存基金业务元数据与申赎规则版本；ClickHouse `gy_dw` 继续保存行情、事件、舆情时序数据；MinIO `research-reports` 继续保存研报文档，数据库仅保存研报索引。
- 保存时校验字段及记录版本，避免非法输入和并发覆盖；保存失败不得产生半条归档或半条新记录。

## Impact

- 新增规格：[specs/fund-archive/spec.md](specs/fund-archive/spec.md)。
- 技术设计：[design.md](design.md)，包含接口、MySQL 表结构、优先级查询和事务方案。
- 实施清单：[tasks.md](tasks.md)。
- 预计影响代码区域：`frontend/`、`backend/`、`data‑etl/` 及 MySQL 增量 DDL。
- 不修改现有 ClickHouse 与 MinIO 表/对象结构，不让前端直连任何存储中间件。

## Assumptions and Risks

- 现有 `dim_asset` 是通用行情资产维度，并不等同于基金主数据；基金代码、基金管理人、托管人等字段需由基金主数据 ETL 来源提供。若当前没有该基金源文件，本变更仍交付表、接口和页面，缺失数据按空值兜底，不伪造基础信息。
- 本变更采用单条当前生效规则，不处理未来生效的多时间段规则排程；`effective_date` 仅记录业务生效日期。
- 操作人由后端登录态获取；若项目尚未接入认证，使用明确的系统用户标识，禁止信任请求体传入的操作人。
- 风险：ETL 归档旧 ETL 申赎记录时，必须完整填写 `deleted_by`、`deleted_at` 审计字段，否则归档记录审计信息残缺。

## Success Criteria

- 验收用例 AC-01 至 AC-14 全部通过。
- 连续编辑后仅存在一条生效人工记录，历史记录完整保留且已软删除。
- ETL 重跑前后，已有人工值的基金仍展示人工值；无人工值的基金展示最新 ETL 值。
- 查询异常、空值、保存校验失败和并发冲突均符合规格，不出现物理删除或静默覆盖。

## Out of Scope

- 基金档案之外的行情、事件、舆情和研报页面开发。
- 申赎规则的历史记录页面、物理删除、人工记录清除及批量导入页面。
- 费率分档、未来生效规则排程、审批工作流和权限体系重构。
